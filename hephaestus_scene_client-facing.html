Project overview

Knauf VR Training Academy is a Meta Quest VR application built on Unity 2022.3. There is no web or desktop variant — it is Quest-only. The app has two content modes: KTA (Knauf Training Academy — the product showroom) and VPT (Virtual Plant Tour — a walkthrough of a real Knauf glass-wool factory). Which mode loads is controlled by a build-time configuration switch. Both modes share the same startup sequence but branch into entirely separate environments from there.

The VPT factory tour follows the real Knauf manufacturing process in order: Waiting Room → Tour Entrance → Starting Room → Binder Room → Batch House → Furnace → Fiberizing → Curing & Cooling → Cutting → Packaging → Warehouse & Distribution. Players can also jump to any room directly via the in-VR Facility Map menu. Each room supports forward and back portal navigation.

All external services and SDKs this project connects to at runtime or during the build pipeline. None of these are optional — removing any one would require code changes.

Unity Gaming Services
UNITY CCD

Cloud Content Delivery — remote CDN for VPT scene bundles

Hosts the compressed Addressable asset bundles for all 9 VPT factory rooms (01_TourEntrance through 09_WarehouseAndDistribution). On each app launch the headset fetches a remote catalog, compares content hashes, and downloads only changed bundles — no App Lab submission needed for content updates. Bundles are cached on-device so no network connection is required during play.

UNITY AUTHENTICATION

Anonymous sign-in — silent session token for Cloud Code access

Runs automatically when the player enters 00_WaitingRoom. No login screen is shown — the SDK signs the player in anonymously and returns a session token. That token is required to authorise any calls to Unity Cloud Code. Without it, the access code gate cannot function.

UNITY CLOUD CODE

Server-side access code validation — CheckAccessCode module

The player types a code on the in-VR keypad in the WaitingRoom. That code is sent server-side to the VPTAccessService/CheckAccessCode Cloud Code module, which returns true or false. No validation logic lives on the device — codes can be managed without rebuilding the app.

UNITY BUILD AUTOMATION

CI/CD pipeline — automated Addressables build and CCD upload

CloudBuildConfigurator.cs reads the CLOUD_PROFILE_NAME environment variable set in Unity Build Automation to determine which CCD bucket to target. When a build is triggered, Addressables bundles are automatically packaged and uploaded to CCD as part of the pipeline — no manual upload step required.

Third-party services
MIXPANEL

Analytics — training event tracking across KTA and VPT

Tracks the following events: Environment_Entered, Environment_Exited, Level_Started, Level_Completed, Level_Exited, Module_Entered, Module_Exited, plus timed event durations. All tracking is handled by AnalyticsManager.cs. Data is sent to the Mixpanel project associated with the app's API key — no on-device storage of analytics data.

Hardware SDK
META XR SDK

Quest controller haptics and in-editor VR simulation

Two Meta XR packages are included: com.meta.xr.sdk.haptics (67.0.0) for controller vibration feedback during interactions, and com.meta.xr.simulator (81.0.0) for testing the experience inside the Unity editor without a physical headset. Neither package communicates with an external server at runtime — both are local device SDKs.

Q1 · ⚠ ORPHAN SCENE

01_StartingRoom is not in the Addressable/CCD system. Was this intentional, or should it be migrated?

Every other VPT room (02–09) is hosted on Unity CCD and can be updated without an App Lab submission. 01_StartingRoom is missing from the Addressable group entirely — the code falls back to SceneManager.LoadSceneAsync, loading it directly from the APK. The script StartingRoomAditivePortal.cs is explicitly marked TODO / temp in the codebase.

If not addressed

Any bug fix or content tweak to StartingRoom requires a full APK rebuild and a new App Lab submission — a process that can take days and blocks all other updates.

As VPT grows, StartingRoom will increasingly fall out of sync with the remote update pipeline. If Knauf ever needs to push a fix to that scene independently, there is currently no path to do so without a code change.

Connecting Locally via SSH (Windows 11)

Azure DevOps only supports RSA SSH keys (not ed25519). Follow these steps to clone the repo to your local machine. Requires Git for Windows and Git LFS.

STEP 1 — Install Git & Git LFS

Download Git for Windows from git-scm.com/download/win — Git LFS is bundled in this installer. After installing, open PowerShell and run:

git lfs install

STEP 2 — Generate RSA SSH Key

In PowerShell, run:

ssh-keygen -t rsa -b 4096 -C "dev@makeway.is" -f "$HOME/.ssh/id_rsa"

Press Enter to skip passphrase (or set one for extra security). This creates two files in C:\Users\YourName\.ssh\:
id_rsa — private key (never share)
id_rsa.pub — public key (this is what you share)

STEP 3 — Start SSH Agent & Add Key

Get-Service ssh-agent | Start-Service
ssh-add "$HOME/.ssh/id_rsa"

STEP 4 — Copy Public Key

cat "$HOME/.ssh/id_rsa.pub"

Copy the entire output (starts with ssh-rsa). Do not include any extra spaces or line breaks.

STEP 5 — Add Key to Azure DevOps

1. Go to dev.azure.com and log in
2. Click your profile icon → SSH public keys
3. Click + New Key
4. Give it a name (e.g. "Makeway Dev Windows")
5. Paste your public key and click Save

STEP 6 — Get SSH Clone URL & Clone

1. Go to the quest-app repo in Azure DevOps
2. Click Clone → switch to the SSH tab → copy the SSH URL

Then in PowerShell:
git clone <SSH URL>
cd quest-app
git lfs fetch origin --all

STEP 7 — Verify Connection

ssh -T git@ssh.dev.azure.com

A successful response confirms the SSH connection is working.

Build & Deploy Pipeline
FULL PIPELINE

End-to-end flow from code change to headset

1. Make code changes locally → push to quest-app repo on Azure DevOps
2. Merge main → release (KTA) or release-vpt (VPT)
3. Trigger a Clean Build in Unity Cloud Build Automation
4. Wait ~2 hours (KTA) or ~2.5 hours (VPT) for build to complete
5. Download the .apk from Unity Cloud (three-dot menu → Download .APK)
6. Open Meta Quest Developer Hub → App Distribution tab
7. Select the appropriate app → Upload to Business channel
8. Wait ~20 minutes for Meta servers to process
9. Build automatically distributes to all enrolled headsets in the relevant device group
